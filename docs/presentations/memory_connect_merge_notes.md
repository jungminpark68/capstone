# 통합 출처와 정리 기준

## 사용한 세 자료

- A: 기억꽃_캡스톤_발표자료_개편본.pptx — 17장
- B: 2026-2_캡스톤디자인 중간발표_1조.pptx — 10장
- C: capstone_project_feedback_7min.pptx — 앞서 작성한 사용자 파트·전체 기획 자료 12장

## 중복·차이를 정리한 기준

- 프로젝트명은 기존 대화와 B·C의 **기억잇다**로 통일했습니다. 기억꽃이라는 명칭으로 별도 프로젝트를 새로 만들지 않았습니다.
- 자료마다 사용 연령이 달라, 본문은 기억력 변화를 느끼며 일상생활·기본 앱 조작과 자발적 참여가 가능한 고령자로 통일했습니다. SCD를 앱이 진단한다고 설명하지 않습니다.
- 추천은 B의 구체적인 모듈 설명을 우선했습니다. **시간·사람·장소별 최대 3개**이며, 시간은 기본 1개월 ±7일, 3개월·12개월 선택 가능입니다. 이전 C의 기간별 대표 1개 방식은 통합본에 사용하지 않았습니다.
- B의 로컬 규칙 기반 회상 질문과 C의 AI 기반 오늘 경험 대화를 구분했습니다. 모든 질문이 AI 생성 또는 모두 로컬 규칙이라고 합치지 않았습니다.
- A의 가족 음성·GPS·안부 확인·접근성 설계, B의 추천·회상 상세, C의 일기·일정 처리와 비교 설계를 연결했습니다.
- 표지 이름과 날짜는 B 자료의 1조·염민호·박정민·정건수·2026.11.6을 사용했습니다. 학번을 임의로 채우지 않았습니다.
- **86개 테스트 / 11개 검사 묶음 / 100개 시나리오 / 114개 가상 과거 자료**는 서로 다른 단위와 용도입니다. 합산하거나 실사용자 수로 표시하지 않았습니다.
- 86개 테스트는 이 대화에서 확인한 결과입니다. B의 11개 묶음과 추천 실행 예시는 업로드 자료의 기록을 사용했으며 코드가 없어 이번 작업에서 재실행했다고 주장하지 않았습니다.
- 팀원의 원본 그림 4장과 실제 구현 화면 1장을 보존·재배치했습니다. 글과 표·도식은 편집 가능한 객체로 새로 작성했습니다.

## 페이지별 출처와 근거 범위

### 1. 기억잇다  /  2026-2 캡스톤디자인 중간발표
- 통합 출처: A 1·5·17 / B 1 / C 1
- 근거·범위: 명칭은 기존 프로젝트명 기억잇다로 통일. A의 기억꽃 명칭은 표지에 병기하지 않음. 팀원·발표일·표지 그림은 B 자료에서 가져옴. 학번은 원문에서 미정이므로 임의 생성하지 않음.

### 2. 기억잇다  /  문제 발견과 대상 선정
- 통합 출처: A 2~4 / B 2 / C 2·4
- 근거·범위: 부모님 경험은 진단이나 대표성 있는 사용자 조사가 아님. 자료 간 60~70대·60세 이상·65~75세 차이가 있어 연령만으로 앱 사용 능력을 가정하지 않고 기능적 사용 조건을 본문에 통일. Jessen et al. (2014), DOI 10.1016/j.jalz.2014.01.001.

### 3. 기억잇다  /  연구 결과와 설계 적용
- 통합 출처: B 4 / C 3 / A 3·15
- 근거·범위: Felinto (2025)와 Souza (2013)의 제목·DOI·초록은 앞선 작업에서 확인. Dijkstra & Janssen (2016) DOI 10.1177/2158244016646412의 초록을 이번 작업에서 확인. 인물·장소 기반의 다른 기록 추천 자체를 임상적으로 검증한 논문으로 해석하지 않음.

### 4. 기억잇다  /  전체 서비스와 기술 구조
- 통합 출처: A 5·6·14 / B 3·5 / C 5
- 근거·범위: B 자료의 과거 검색·첫 질문·꼬리질문 선택은 API 없는 규칙 처리이며, C의 오늘 경험 질문 생성 API와 구분. 마이크 인식·가족 음성 재생의 네트워크 여부는 검색 로컬 처리와 별개. 외부 DB·가족 음성·GPS 전체 구현 완료라는 주장을 하지 않음.

### 5. 기억잇다  /  대화·그림일기·일정
- 통합 출처: A 7·8·10 / C 6·8·11 / 현재 앱 화면
- 근거·범위: 일기 생성·일정 분리·거절 처리·저장 안정성은 현재 C의 핵심 웹 코드 기준. 경험별 장소·시간·인물 저장은 팀 통합 데이터 설계로 설명하며 현재 makeEntry가 모두 구현했다는 의미가 아님. 화면은 앞선 작업의 독립 브라우저에서 캡처한 실제 확인 카드.

### 6. 기억잇다  /  시점 선택과 후보 조합
- 통합 출처: B 5·6 / C 7의 시점 선택 문제의식
- 근거·범위: 업로드 B의 구체 모듈 설명을 통합 기준으로 채택. 이전 C의 1·3·12개월별 대표 1개 방식은 채택하지 않음. B의 실제 설명: 시간 점수=100-기준일 거리×3, 사람=90+min(2,공통 인물수)×5, 장소명=100, 유형=80. 최근 3일 미만 노출 -15, 14일 미만 -5. 추천 개수 확보를 먼저 고려하고 조합 합계 점수 비교, 동점은 날짜·ID로 정렬. 수치는 초기 설계값이며 측정된 성능·임상 최적값이 아님. 등록 문자열을 정규화하여 비교하므로 동명이인/관계명만 같은 다른 인물 자동 식별과 얼굴 인식을 주장하지 않음.

### 7. 기억잇다  /  추천 결과와 설명 가능성
- 통합 출처: B 7의 텍스트·세 원본 그림·노트
- 근거·범위: B 제공 기록의 입력: 가상 과거 114개, 오늘 입력 park, months=1, now=2026-11-03, 노출 이력 없음. 출력 ID: time sample-diary-v5-044-pool-walking; people sample-diary-v3-handprints; place sample-diary-v1-today-park. 세 점수 100인 사례. 이 작업에서는 팀원 저장소 코드가 첨부되지 않아 독립 재실행한 결과로 제시하지 않음. 그림은 AI 가상 예시이며 실제 가족 사진이 아님.

### 8. 기억잇다  /  규칙 기반 질문 선택·진행
- 통합 출처: B 8·9 / A 7·9 / C 6의 대화 부담 원칙
- 근거·범위: 예시 문답은 B에 기록된 규칙 실행 사례. 자유 한국어 전체를 이해하거나 인지 상태를 자동 평가하는 엔진이라는 주장은 하지 않음. 현재 경험 일기 대화와 과거 회상 대화는 서로 다른 모듈이며 모든 대화가 최대 3문답이라는 뜻이 아님.

### 9. 기억잇다  /  일상에서 사용을 이어주는 설계
- 통합 출처: A 10~14 / B 3·10 / C 8·9
- 근거·범위: 가족 음성·GPS 전체 연계는 제공 자료의 설계 범위. 통합 시연의 완료 결과나 실제 알림 전송을 새로 만들지 않음. 참여 횟수와 기억꽃 등 격려는 인지능력 점수나 의료 지표로 사용하지 않음. API 키는 서버에 보관하는 원칙을 아키텍처 설명에 포함. 실제 위치만으로 방문·진료 수행 완료를 추정하지 않음.

### 10. 기억잇다  /  무엇을 연결했고, 어떻게 평가할 것인가
- 통합 출처: C 10 / B 6·8·10 / A 15
- 근거·범위: 기준선과 서비스의 입력·모델 설정·질문 수·제시 시간을 맞추고 순서와 재노출을 통제하는 평가 설계. 모델 및 사용자 비교의 개선율을 임의로 만들지 않음. 문장·그림 품질의 동등성을 주장하려면 사전 허용 기준과 반복 비교가 필요.

### 11. 기억잇다  /  실행 근거와 평가 범위
- 통합 출처: B 9의 실제 화면·검사 기록 / C 11의 86개 테스트 / A 15
- 근거·범위: 86개는 이 대화에서 확인한 핵심 웹 코드 테스트 결과. 11개 묶음·100개 가상 시나리오는 B가 제공한 2026-10-31 검사 기록이며 이번 작업에서 독립 재실행한 결과가 아님. B의 114개 가상 과거 기록 추천 사례와 100개 가상 일상 시나리오를 동일 데이터 개수로 합산하지 않음. 사용자 실제 사진·장기 사용성·인지 효과 측정 결과로 제시하지 않음.

### 12. 기억잇다  /  결론과 피드백
- 통합 출처: A 17 / B 10 / C 12·참고자료
- 근거·범위: 주요 참고자료는 원문으로 연결되는 하이퍼링크 포함. 의료적 효과나 최적 추천 기준을 입증했다는 표현을 피하고 설계 타당성·사용성·과업 수행을 중간발표의 질문으로 설정.
