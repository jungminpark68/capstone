# 기억잇다 · 무료 그림 자료와 순정/LoRA 비교

이 묶음에는 소스를 포함한 Kaggle 노트북 두 개가 있습니다. API 키나 유료 이미지 호출 없이 실행합니다. 공개 모델 다운로드에는 Internet이 필요하며 Kaggle 무료 GPU 시간·디스크 한도는 적용됩니다.

- 01_free_diary_data.ipynb: SDXL로 색연필풍 그림 생성, 사람 정답 검토, 자료 분할.
- 02_pretrained_vs_lora.ipynb: 같은 공개 판정 모델의 순정 → 일반 LoRA → 오류 특화 LoRA 비교.

실제 SDXL 생성과 Kaggle GPU 학습은 배포 환경에서 측정하지 않았습니다. 코드·자료 분할·저장/복원·작은 무작위 Qwen3-VL 모델의 LoRA 학습 생명주기를 로컬에서 검증했습니다. 정확도 결과나 완성된 학습 가중치는 넣지 않았습니다.

## v0.17 · 1번의 자동 초벌 라벨

1번만 갱신하는 ZIP에는 01_free_diary_data.ipynb와 이 안내가 들어 있습니다. 기존 2번은 그대로 사용할 수 있습니다. 2번의 DATA_MODE="reviewed"와 DATA_DIR로 검토 완료 자료를 연결합니다.

1번은 SDXL 생성 후 무료 공개 VLM으로 학습/검증용 초벌 라벨을 만듭니다. 기본 RUN_DRAFT_LABELS=True이며 DRAFT_MODEL은 Qwen/Qwen3-VL-4B-Instruct입니다. 그림 생성 모델과 판정용 초벌 모델은 서로 다릅니다. 두 모델은 순차 프로세스로 실행하며 이미지당 유료 API 호출은 없습니다. 초벌 계산에도 GPU 시간이 듭니다.

검토 화면에서 초벌 답이 미리 선택됩니다. 그림과 원래 사실을 확인하고 틀린 항목만 수정한 뒤 정답 저장 후 다음을 누릅니다. 저장 전 초벌 답은 학습에 포함하지 않습니다. draft-labels.jsonl에 원래 자동 답, human-review.csv에 최종 사람 답·초벌 답·검토 방식을 따로 남깁니다. 기존 사람 답은 자동 답으로 덮어쓰지 않습니다.

최종 평가용은 초벌 답을 계산·표시하지 않으며 직접 판정합니다. 사건별 분할은 초벌 단계에서 고정하고 생성 장수를 늘려도 유지합니다. 고정 분할은 사건 순서에 따라 대략 학습 60%·개발 20%·시험 20%를 배정합니다. 검토 완료 사건이 각 분할에 충분해야 자료를 내보낼 수 있습니다. 같은 이미지가 다른 분할에 있으면 내보내기를 중단합니다.

생성·초벌이 끝나면 RUN_GENERATION=False, RUN_DRAFT_LABELS=False로 바꾸고 GPU를 꺼서 검토합니다. 분할 기록·초벌 파일·검토 CSV는 source 폴더와 함께 보관합니다. 원래 이야기나 그림이 바뀌면 이전 초벌을 재사용하지 않습니다. 자료를 내보낼 때 초벌 후 수정 여부도 함께 보존합니다.

자동 초벌은 틀릴 수 있으며 같은 모델의 제안을 보고 검토한 개발 자료에는 편향이 생길 수 있습니다. 최종 시험은 예측을 숨긴 사람 정답으로 비교합니다. 자동 라벨링 정확도를 측정했다는 의미는 아닙니다.

## 왜 LoRA인가

LoRA는 큰 사전학습 모델의 일부 보정 파라미터만 학습하는 방법입니다. 판정기에 본질적으로 더 정확한 방식이라고 가정하지 않습니다. Kaggle GPU에서 메모리를 절약하면서 사전학습 모델을 우리 작업에 맞춰 학습하기 위한 선택입니다.

이번 LoRA 대상은 **그림을 그리는 SDXL이 아니라 그림·사실을 대조하는 판정 모델**입니다. SDXL은 학습하지 않고 생성에만 사용합니다.

| 조건 | 추가 학습 | 확인할 효과 |
|---|---|---|
| A · pretrained | 없음 | 원래 모델의 판정 성능 |
| B · plain | 사실별 일치/불일치/판단 불가 LoRA | A→B: 우리 정답 자료로 학습한 효과 |
| C · relation | B와 같은 설정 + 같은 사실의 정상/오류 그림 쌍 대조 손실 | B→C: 오류 대조 학습의 추가 효과 |

기존 언어모델의 출력층에서 A/B/C 다음 토큰 점수를 비교합니다. 무작위 판정층을 붙인 모델을 순정 기준선으로 삼지 않습니다. 세 점수로 정규화한 값은 보정된 확률이 아닙니다. 자유롭게 답을 생성하는 모든 사용 방식의 성능도 아닙니다.

B/C는 기반 가중치 revision·프롬프트·학습/검증 자료·시드·배치·학습률·LoRA 크기·학습 횟수 예산을 맞춥니다. 기본적으로 대조 손실 가중치만 0과 0.25로 다릅니다. 같은 쌍을 포함하는 배치를 두 조건 모두 사용합니다. 조건마다 최적 epoch는 개발셋으로 고릅니다. 비전 인코더와 원래 LM 출력층은 고정하고 언어모델 내부 LoRA를 학습합니다.

LoRA 자체나 일반적인 대조 손실을 우리의 신규 기술이라고 주장하지 않습니다. 오류 데이터와 사실 관계의 설계, 오류 특화 학습 구성, 통제된 비교에서 실제 개선되는지를 보여주는 것이 과제입니다. C가 B보다 반드시 좋아진다고 가정하지 않습니다.

## ① 무료 색연필풍 그림 만들기

1. Kaggle에서 새 Notebook을 만들고 File → Import Notebook으로 01 파일을 불러옵니다.
2. GPU와 Internet을 켭니다.
3. 처음에는 TOTAL_IMAGES=20으로 실행하고 그림을 확인합니다.
4. 화풍이 적합하면 TOTAL_IMAGES를 100, 300, 1000으로 올려 생성 셀을 다시 실행합니다.

기본 생성 모델은 stabilityai/stable-diffusion-xl-base-1.0입니다. 현재 앱의 명료한 색연필 요청문에 맞춰 윤곽선·파스텔 색면·색연필 결·인물과 사물의 구별을 강조합니다. 같은 모델·동일한 그림체를 보장하지 않습니다. 먼저 소량을 확인해야 합니다. 화풍이나 생성 설정을 바꾸면 SOURCE_NAME을 새 이름으로 지정합니다.

기본 설정:

    SOURCE_NAME = "pencil-sdxl-v1"
    TOTAL_IMAGES = 20
    DATA_SEED = 42
    STEPS = 25
    SIZE = 1024
    GUIDANCE = 6.5
    CPU_OFFLOAD = True

CPU_OFFLOAD는 GPU 메모리를 절약하며 속도가 느려질 수 있습니다. 충분한 GPU 메모리가 있다면 False로 시험할 수 있습니다. CUDA/라이브러리/장치에 따라 속도와 결과가 달라지므로 장당 생성 시간을 미리 확정하지 않습니다.

11가지 생성 의도는 정상, 역할 교환, 인물 누락/추가, 사물 누락, 수량, 배경, 좌우, 색상, 인물 가림, 사물 가림입니다. **의도대로 그려졌다는 보장이 없으므로 정답을 자동으로 붙이지 않습니다.** 초기 자료는 두 배경과 네 행동 중심이라 1,000장이 곧 다양한 일상 1,000종을 의미하지 않습니다. 주제·등장인물·구도 확장은 실제 결과를 보고 보완합니다.

### 이어 만들기

그림마다 고정된 생성 시드와 요청문을 저장합니다. 그림을 한 장 만들 때마다 생성 목록과 빈 정답표를 저장합니다. 같은 SOURCE_NAME과 설정으로 실행하면 기존 그림의 지문을 확인하고 없는 그림만 추가합니다. TOTAL_IMAGES 증가는 허용하고 기존 사람 정답은 보존합니다.

세션이 끝나기 전 마지막 ZIP 셀을 실행하고 Kaggle Output을 저장합니다. 새 세션에서는 ZIP의 source 폴더를 풀어 Kaggle input에 연결하고 RESTORE_SOURCE_DIR를 해당 source 폴더로 지정하면 작업 폴더로 복사합니다. 큰 모델 캐시는 결과 ZIP에서 제외합니다.

## 학습·평가 데이터가 의미하는 것

모델 입력은 **그림 + 원래 그리고자 했던 사건 + 인물 구별 기준 + 판정할 사실 하나**입니다. 정답은 별도로 둡니다.

예:

- 원래 이야기: 손녀가 자전거를 타고, 나는 벤치에 앉아 응원했다.
- 인물 구별: A는 파란색 상의 어르신, B는 노란색 상의 아이.
- 확인 사실: B가 자전거를 타고 있다.
- 사람 정답: 실제 그림을 보고 일치/불일치/판단 불가 중 선택.

생성된 그림을 보고 새로 만든 설명을 원래 이야기 대신 사용하면 잘못 그린 내용도 맞는 것으로 바뀔 수 있습니다. 시각적 사실과 원래 이야기를 대조해야 합니다.

날짜·실명·가족관계·감정·중요도는 그림만으로 증명하지 않습니다. 앱의 회상 매칭용으로 보관할 수 있지만 시각적 판정 정답과 구분합니다. 가족관계 대신 확인한 옷 색 등의 구별 기준으로 인물–행동 연결을 검사합니다.

1,000장 × 사실 8개는 사실 판정 8,000개입니다. 같은 그림의 사실 8개를 독립적인 그림 8장처럼 세지 않습니다. 같은 사건의 모든 생성 의도는 같은 분할에 들어갑니다.

## 사람 정답 검토

그림 생성 후에는 RUN_GENERATION=False와 RUN_DRAFT_LABELS=False로 바꾸고 Kaggle GPU를 꺼서 정답 검토만 할 수 있습니다. 검토 중 무료 GPU 할당을 계속 소모할 필요가 없습니다. 새 세션이면 먼저 source 폴더를 복원합니다.

01 노트북의 검토 화면에서 검토자 ID를 입력하고 그림별 모든 사실을 판정한 뒤 저장합니다. human-review.csv를 직접 편집해도 됩니다.

- supported: 그림에서 사실을 확인할 수 있음.
- contradicted: 그림과 명확히 충돌하거나 필수 대상이 명확히 누락됨.
- uncertain: 가림·모호함 등으로 판단할 수 없음.

요청한 오류 종류와 모델 예측은 검토 화면에서 숨깁니다. 처음부터 정상이라고 가정하거나 정답을 맞춰 바꾸지 않습니다. 모든 사실에 라벨과 검토자 ID가 있는 그림만 포함하고 미완료 그림은 제외·집계합니다. 정식 시험 자료는 독립 재검토와 이견 조정이 필요합니다.

최소 6개 독립 사건을 검토하고 BUILD_REVIEWED=True로 바꿔 자료 준비 셀을 실행합니다. 같은 사건·이미지가 학습/개발/시험에 섞이지 않도록 분리합니다. 학습에는 세 정답 종류가 모두 필요하며 대조 학습에는 같은 사실의 일치/불일치 그림 쌍이 필요합니다. 부족하면 추가 검토·수집합니다.

자료 버전을 바꾸려면 REVIEWED 폴더 이름도 새 버전으로 바꿉니다. 검토 자료 생성은 기존 폴더를 덮어쓰지 않습니다.

## ② 순정·LoRA 비교 실행

1. 01의 결과 ZIP에서 reviewed 폴더를 Kaggle 데이터셋에 연결합니다.
2. 02 파일을 Import Notebook으로 열고 GPU·Internet을 켭니다.
3. DATA_MODE="reviewed"로 바꾸고 DATA_DIR를 reviewed 폴더 경로로 지정합니다.
4. 먼저 개발 단계까지 실행합니다. RUN_FINAL_TEST는 False로 둡니다.

자료가 아직 없으면 기본 schematic 모드로 전체 학습 연결을 확인할 수 있습니다. 이 자료는 코드 도식형 그림과 규칙 정답이며 실제 SDXL 성능이 아닙니다. reviewed 모드에 자료가 없으면 오류를 내고 도식으로 자동 대체하지 않습니다.

기본 공개 판정 모델은 Qwen/Qwen3-VL-4B-Instruct입니다. Kaggle에서 실행할 초기 후보이며 최고 성능 모델로 검증한 선택은 아닙니다. 다른 지원 후보를 BASE_CANDIDATES에 추가하면 순정 모델의 개발셋 Macro-F1로 하나를 고릅니다. 순정 후보 순위가 파인튜닝 후 순위를 보장하지는 않습니다.

기본 학습 설정:

    EPOCHS = 2
    BATCH_SIZE = 2
    ACCUMULATION = 4
    LEARNING_RATE = 1e-4
    LORA_RANK = 16
    PAIR_WEIGHT = 0.25
    TRAIN_SEED = 42
    FOUR_BIT = True
    MAX_PIXELS = 200704
    BALANCED = True
    RUN_FINAL_TEST = False

EPOCHS는 최대 반복 횟수, ACCUMULATION은 여러 미니배치의 기울기를 모으는 횟수입니다. FOUR_BIT=True이면 A/B/C 모두 같은 기반 가중치의 4-bit 양자화를 사용합니다. 따라서 A는 원래 full-precision 모델 전체 성능이 아니라 같은 양자화 조건에서 추가 학습이 없는 기준선입니다. GPU 두 개의 메모리가 자동으로 합쳐지지는 않으며 이 노트북은 한 GPU씩 사용합니다.

B/C의 최적 체크포인트는 개발 Macro-F1로 고르고 동점이면 개발 loss를 비교합니다. 기반 모델과 최종 사용할 방법도 개발셋으로 고릅니다. 개발 성능표는 최종 성능이 아닙니다.

성능을 높이는 탐색은 학습률·학습 횟수·자료 수·대조 가중치를 개발셋에서 비교합니다. 무조건 더 많은 epoch·더 큰 LoRA가 좋은 것은 아닙니다. 설정마다 새 실행 폴더를 쓰고 자료 버전과 분할을 고정합니다. 정식 반복 검증은 시드를 바꾸어 B/C 한 쌍씩 동일 조건으로 실행합니다.

## 최종 시험과 결과

튜닝을 마친 뒤 RUN_FINAL_TEST=True로 바꾸고 최종 시험 셀만 실행합니다. 계획·자료·가중치 지문을 검증한 뒤 A/B/C를 같은 시험 자료로 평가합니다. 시험이 시작된 실험에서는 추가 개발을 막습니다. 시험 결과를 보고 다시 튜닝한다면 별도의 새 최종 시험 자료가 필요합니다.

출력은 HTML/CSV/JSON 성능표, 혼동행렬, Macro-F1, 오류 검출률, 오류 그림의 정상 통과율, 정상 오경보율, 보류 비율과 사건 묶음 단위 신뢰구간입니다. 독립 사건이 너무 적으면 신뢰구간을 계산할 수 없거나 매우 불안정합니다.

그림·정답·실제 A/B/C 예측을 나란히 표시합니다. 예시 화면은 오분류가 많은 그림을 우선 보여주며 전체 성능은 모든 해당 자료로 계산합니다.

## 해석의 범위

- 도식 자료 결과: 합성 도식에서의 판정 성능.
- 사람 검토 SDXL 자료 결과: 해당 SDXL 색연필풍 대체 자료에서의 판정 성능.
- 실제 앱 자료 결과: 별도 확보·검토한 앱 자료 범위의 판정 성능.

SDXL로 학습한 모델이 앱의 다른 생성 모델 그림에도 잘 작동하는지는 별도 확인해야 합니다. 인공적으로 오류를 많이 만든 스트레스 자료는 생성 모델의 자연 오류율을 측정하지 않습니다. 이 기술 비교는 회상·인지 개선 효과의 임상 검증이 아닙니다.
