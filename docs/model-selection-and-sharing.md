# 한국어 임베딩·매칭·그림 검증 모델의 후보와 공유 범위

초기 구현은 **BGE-M3 텍스트 인코더 + SigLIP2 Base-384 그림 인코더 + 직접 학습하는 연결·분류 모듈**로 진행한다. 두 인코더는 동결하며, 기본은 사실별 문장 벡터 하나로 그림 패치를 비교하는 방식이다. 원래 토큰 특징이 있으면 별도 `tokens` 실험도 가능하다. 캐시·학습·추론·앱 연결은 구현했고 실제 사전학습 인코더의 한국어/이미지 입력을 확인했다. 실제 사람 정답 자료를 수집하기 전이므로 연구용 학습 가중치·정확도 결과는 없으며 최적 모델 선정이나 공동 학습 완료를 의미하지 않는다. ## 후보

| 후보 | 주 용도 | 이 프로젝트에서의 판단 |
|---|---|---|
| BGE-M3 | 다국어 문장·문서 임베딩 | 한국어 공통 텍스트 인코더의 우선 비교 후보. 이미지 인코더는 아니므로 그림과 직접 코사인 비교할 수 없음 |
| multilingual-E5-base | 한국어 포함 다국어 텍스트 검색 | 더 가벼운 공통 문장 인코더 비교 후보. 모델의 query/passage 입력 규칙을 유지해야 함 |
| ko-sroberta-multitask / KoSimCSE | 한국어 문장 임베딩 | 한국어·작은 규모 비교 후보. 실제 일기의 메인·보조 단서와 역할 차이를 구별하는지 확인 |
| CLIP | 이미지–문장 인코딩·유사도 | 가벼운 기준 모델. 일반 영어 중심 체크포인트의 한국어와 인물–행동 결합 이해는 별도 검증 필요 |
| SigLIP 2 Base / SO400M | 다국어 이미지–문장 인코딩, 지역 시각 특성 | 공유 멀티모달 인코더 또는 검증용 이미지 인코더 후보. 공식 다국어 성능이 한국어 회상 일기에서의 최적 성능을 의미하지 않음 |
| BLIP ITM | 이미지–문장 일치 분류 | 거대 채팅 모델 없이 교차 어텐션 기반 판정기를 만드는 후보. 영어 중심 텍스트 처리의 한국어 대응이 필요 |
| CLIP-FlanT5 / BLIP-2 | 이미지 질문·문장 대조 | VQA 기반 판정 기준. 영어 중심이며 언어 대응과 모델 크기를 확인해야 함 |
| Qwen3-VL-8B / Qwen3.5-9B | 다국어 이미지·문장 이해·추론 | 강한 VLM 비교 후보. 작은 인코더 기반 방법이 핵심 오류에서 충분한지 보기 전에 주력으로 확정하지 않음 |

SigLIP 2 Base-384의 공식 저장소 safetensors 총 파라미터는 약 3.75억, SO400M-384는 약 11.36억이다. 이름의 SO400M을 전체 모델 크기로 읽으면 안 된다. 파라미터 수만으로 정확도·GPU 학습 메모리를 판단하지 않는다.

CLIP/SigLIP의 전체 이미지–문장 유사도는 그 자체로 완성된 사실 판정기가 아니다. 같은 사람·사물이 있고 역할만 바뀐 그림에서 높은 유사도가 나올 수 있다. 패치·인물 영역과 사실 문장 토큰을 연결하는 별도 판정 모듈을 학습하고 확인할 필요가 있다.

## 권장 공유 범위

초기 구조는 **공통 한국어 텍스트 인코더 + 별도 매칭 모듈 + 별도 이미지·사실 검증 모듈**로 검토한다.

- 매칭 모듈: 오늘과 과거의 메인 사건·인물·장소·활동·기억 단서와 실제 회상 반응을 보고 관련 자료를 순위화한다.
- 검증 모듈: 선택 장면의 확인된 사실, 인물 구별 설정, 그림의 패치/영역 특징을 보고 일치·불일치·판단 보류를 분류한다.
- 생성 단계: 사용자가 확인한 메인 장면을 중심으로 구성하고, 그림 밖 다른 사건은 전체 일기 정보로 보관한다.

BGE-M3 문장 벡터와 CLIP/SigLIP 이미지 벡터는 같은 크기로 맞춘다고 자동으로 같은 의미 공간이 되지 않는다. 연결용 projection·cross-attention을 실제 이미지–사실 주석으로 학습하거나, 이미 이미지와 문장이 함께 학습된 SigLIP 2의 양쪽 인코더를 사용한다.

## 팀원이 매칭용으로 학습한 모델을 재사용해도 되나

재사용할 수 있다. 다만 다음은 분리한다.

1. **인코더 가중치**: 초기화나 동결된 특징 추출기로 재사용 가능.
2. **매칭용 어텐션·개인별 가중치**: 관련 경험을 찾기 위한 기준이며 그림의 사실 판정 기준으로 복사하지 않음.
3. **오토인코더의 압축 벡터**: 작은 역할·수량 정보가 사라졌을 수 있다. 우선 사실별 문장 벡터와 원래 구조화 사실을 제공하고, 가능하면 압축 전 토큰 특징도 비교한다. 문장 벡터를 임의로 늘려 토큰 특징인 것처럼 쓰지 않는다.

‘손녀와 공원에서 자전거’와 ‘할머니와 공원에서 자전거’는 매칭에서 관련성이 높을 수 있지만, 같은 그림의 행동 주체 판정에서는 구별되어야 한다. 공유 모델을 한쪽 과제로 계속 갱신하면 다른 과제에 필요한 정보가 약해질 수 있다.

처음에는 매칭용 체크포인트를 복사·동결하고, 검증 전용 이미지 연결부와 분류기만 학습한다. 다음을 같은 이미지 인코더·자료·분류기 조건에서 비교한다.

- 원래 사전학습 텍스트 인코더에서 출발.
- 팀원의 매칭 학습 인코더에서 출발.
- 필요할 경우 과제별 adapter 또는 공동 학습.

팀원의 원본 체크포인트를 검증 학습으로 덮어쓰지 않는다. 공유 후보를 채택할지는 두 과제의 성능을 모두 보고 결정한다. 공유가 항상 별도 모델보다 좋은 것은 아니다.

## 데이터·인터페이스 약속

공통으로 모델명/버전, tokenizer, 최대 토큰 수, pooling, 압축 전후 특징의 차원과 의미, 학습에 사용한 사건 ID를 공유한다. 모델 입력은 화풍 지시나 표현용 옷 색이 섞인 생성 프롬프트가 아니라 확인된 경험 정보다.

같은 사건의 기록·그림·변형본은 팀 전체에서 공통 분할을 먼저 정한다. 검증기의 최종 시험 사건이 매칭 모델의 미세조정·오토인코더 학습에 들어간 경우 일반화 평가가 오염될 수 있으므로 분리하거나 transductive 평가로 명시한다.

전체 일기를 짧은 인코더에 넣어 뒤를 자동으로 잘라내지 않는다. 메인 사건, 보조 사건, 인물별 행동, 장소, 시간, 기억 단서로 나눠 인코딩하며 미확인/없음/미수집 상태를 구분한다. 어텐션 가중치나 오토인코더의 복원 중요도가 곧 실제 회상 효과의 중요도라고 주장하지 않는다.
