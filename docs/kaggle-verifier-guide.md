# 기억잇다 v0.14 · 생성·판정 통합과 Kaggle 실행

그림일기 생성 → 생성 당시 사실 목록으로 판정 → 일치·불일치·판단 보류 표시 → 그림과 판정 함께 저장하는 흐름입니다.

학습된 연구용 가중치와 실제 정확도 수치는 동봉하지 않았습니다. 소프트웨어 테스트용 임의 특징·가중치는 실제 판정 서버에서 거부합니다. 앱의 AI 판정을 사람 정답으로 자동 사용하지 않습니다.

## 내려받을 파일

- `memory-connect-v0.14.zip`: Node 웹앱, 생성·판정 통합 화면, 연구용 사람 검토 화면, ML 코드 전체.
- `memory-verifier-v0.14.zip`: 앱 없이 사용하는 판정기 Python 코드·Kaggle/Colab 노트북·사용 안내. 거대한 사전학습 모델과 원본 이미지는 포함하지 않습니다.
- 주 노트북: `ml/notebooks/memory_connect_verifier_kaggle.ipynb`.

## 1. 먼저 실제 그림에 사람 정답 붙이기

1. 앱 폴더에 기존 `.env`를 복사하고 `npm start`로 실행합니다. 기존 브라우저 기록은 유지됩니다.
2. 대화 → 한 사건 선택 → 부족한 정보 확인 → 그림 생성으로 진행합니다.
3. 완성 화면의 **판정기 연결 · Kaggle 자료 → 사람 정답 붙이기 · 학습자료 만들기**를 엽니다.
4. 그림을 보고 모든 사실을 직접 **일치 / 불일치 / 판단 보류**로 판정한 뒤 **검토 결과 저장**을 누릅니다. AI 판정을 가리는 옵션을 사용할 수 있습니다.
5. **실험 기록 JSON 내려받기**로 저장합니다. 검토 화면의 수집 기록은 현재 탭에 보관하므로 닫기 전에 내려받습니다. 여러 JSON을 Kaggle에 함께 연결할 수 있습니다.

정상·오류·판단 불가 자료가 모두 필요합니다. 관계 대조 학습에는 **기준 장면·인물·사실이 같고 그림만 다른 정상/오류 쌍**이 필요합니다. 각 그림은 사람이 확인해야 합니다. 의도적으로 만든 오류 자료와 일반 생성 자료를 구분해 관리하세요. 독립된 사건 수가 적으면 일반화 성능을 주장할 수 없습니다.

날짜·가족 신원·첫 성공·감정·중요도는 그림의 사실 판정 정답으로 추정하지 않습니다. 실제 확인 가능한 장소 유형·인물 수·행동 주체·사물·관계를 사용합니다. 미확인·모름·거절을 임의의 사실로 채우지 않습니다.

## 2. Kaggle에 코드와 데이터 연결

1. 판정기 ZIP을 풀고 주 `.ipynb` 파일을 Kaggle의 **Import Notebook**으로 불러옵니다.
2. **Accelerator → GPU**, **Internet → On**으로 설정합니다.
3. 코드 ZIP(또는 압축 해제한 코드)과 사람 검토 JSON을 **비공개 Dataset**으로 연결합니다.
4. 첫 설정 셀의 `MODE`를 선택합니다. 코드가 하나면 경로를 자동 탐색합니다. 여러 버전을 연결했다면 `PROJECT_ZIP` 또는 `PROJECT_PATH`를 지정합니다.

| MODE | 준비물 | 수행 내용 |
|---|---|---|
| `train_and_evaluate` | 실제 그림·사람 판정 JSON | 자료 분리, 특징 추출, 세 방법 학습·평가 |
| `evaluate_only` | 준비된 시험 자료와 학습한 가중치 | 같은 시험 자료로 기존 모델 비교 |
| `predict_diaries` | 앱의 판정 요청 JSON과 학습한 가중치 | 앱으로 가져올 판정 결과 JSON 생성 |

기본 설정은 `sentence`, seed 42, 15 epochs입니다. 정식 반복 실험에서는 `SEEDS=[42,43,44]` 등으로 고정하고 결과를 함께 보관합니다. `RUN_NAME`은 실험별로 바꿉니다. 기존 결과를 조용히 덮어쓰지 않습니다.

동일 사건·이미지·원본/변형본·명시한 prompt family는 같은 묶음에 두고 학습/검증/시험을 분리합니다. 예시 기록은 제외 수를 표시하고 실제 사람 검토 자료만 준비합니다. 정답이 불완전하거나 서로 충돌하면 실행을 중단합니다. 시험 세트의 복수 독립 검토와 불일치 조정은 별도로 수행하세요.

## 3. 비교하는 모델과 평가 파일

- **pooled**: BGE-M3 문장 특징 + SigLIP2 패치 평균 특징 + 분류기.
- **plain**: 같은 인코더 + 사실 문장–그림 패치 교차 어텐션 + 3분류 학습.
- **relation**: plain과 같은 구조·배치·시드 + 같은 사실의 정상/오류 쌍 대조 손실.
- **API(선택)**: 같은 그림·확인 문맥·사실을 범용 이미지 이해 모델에 제공. `RUN_PAID_API=False`가 기본이며 모델 ID와 실행 여부를 직접 설정할 때만 비용이 발생합니다.

BGE-M3와 SigLIP2는 동결합니다. 학습 범위는 결합·판정 모듈이며 인코더 자체의 미세조정을 완료했다는 의미가 아닙니다. 대조 쌍이 없으면 relation은 실행하지 않고 생략 사유를 기록합니다.

출력은 다음과 같습니다.

- `comparison-seed42.html`: 모델별 성능표, 혼동행렬, 오류 유형별 재현율, 사건 묶음 단위 비교 신뢰구간.
- 같은 이름의 `.csv`, `.json`, `.md`: 엑셀·코드·보고서용 결과.
- `seed-summary.csv`: 여러 시드의 평균과 표준편차. 한 번만 실행하면 표준편차는 비워 둡니다.
- `protocol.json`: 자료 해시, 설정, 생략한 실험, 시간 측정 범위.
- 각 모델 폴더: `fusion_head.pt`, `fusion_config.json`, `history.json`.
- `*-results.zip`: 가중치·설정·예측·보고서 묶음. 원본 그림과 API 키는 제외합니다.

Macro-F1, 오류 항목 재현율, 오류 그림의 정상 통과율, 정상 그림 오경보율, 보류 비율을 함께 봅니다. 캐시된 특징으로 측정한 시간은 판정 모듈의 시간입니다. API와 전체 시간을 비교하려면 `MEASURE_END_TO_END=True`를 사용하고 환경·호출 단위도 기록합니다. 실제 임상 효과나 생성 모델 전체 오류율을 이 시험 자료의 결과로 일반화하지 않습니다.

## 4. Kaggle 파일로 앱의 그림 판정

로컬에 Python 서버를 설치하지 않아도 사용할 수 있는 방식입니다.

1. 앱 완성 화면 → **판정기 연결 · Kaggle 자료 → Kaggle 판정 요청 저장**.
2. 요청 JSON과 학습한 가중치를 Kaggle Dataset으로 연결합니다.
3. `MODE="predict_diaries"`, `BATCH_CHECKPOINT="가중치 폴더 경로"`로 실행합니다.
4. `diary-predictions.json`을 내려받습니다.
5. 앱의 같은 그림에서 **Kaggle 결과 불러오기**로 가져옵니다.

그림 SHA-256, 사건 ID, 장면·인물·사실 목록 지문을 대조합니다. 다른 그림·다른 사실의 결과나 불완전한 판정은 가져오지 않습니다. 이 방식은 사람 정답이 없어도 추론할 수 있지만 정확도를 계산하지 않습니다. 그림을 다시 그리면 새 요청을 내보내야 합니다.

## 5. 실시간 자동 판정 연결

Kaggle에서 학습한 판정 모듈을 내려받아 앱을 실행하는 컴퓨터에서 Python 서버를 켭니다. 최초 인코더 다운로드를 위한 인터넷과 디스크 공간이 필요합니다. CPU도 가능하지만 처리 시간은 장치에 따라 다릅니다.

Linux/macOS:

```bash
python -m pip install -r ml/requirements-fusion.txt
PYTHONPATH=ml python -m diary_verifier.fusion_serve --checkpoint ./relation-seed42 --port 8010
```

Windows PowerShell:

```powershell
python -m pip install -r ml/requirements-fusion.txt
$env:PYTHONPATH="ml"
python -m diary_verifier.fusion_serve --checkpoint .\relation-seed42 --port 8010
```

앱 `.env`:

```dotenv
DIARY_VERIFY_BACKEND=local
DIARY_VERIFIER_URL=http://127.0.0.1:8010
DIARY_VERIFY_AUTO=true
```

그 뒤 Node 서버를 다시 실행하면 새 그림 생성 후 자동 판정합니다. Kaggle의 `localhost:8010`은 사용자 컴퓨터에서 직접 접근할 수 있는 주소가 아닙니다. Kaggle에서만 실행할 때는 위 파일 왕복 방식을 사용하세요.

판정 실패·미연결 상태에서는 생성한 그림을 보존하고 미판정으로 남깁니다. 판정만 재시도할 수 있고, 확인을 나중으로 미루고 저장할 수도 있습니다. 새 그림에는 이전 판정을 복사하지 않습니다. API 비교로 자동 대체하지 않으며, API 자동 판정은 `.env`에서 API 방식과 `DIARY_VERIFY_AUTO=true`를 명시할 때만 켜집니다.
