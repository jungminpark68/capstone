# 그림일기 생성 흐름 · v0.13 설계

- 첫 질문은 오늘 특히 기억에 남거나 그림으로 남기고 싶은 일이 있었는지 묻는다. 특별한 일이 없다고 하면 그때 오늘을 어떻게 보냈는지 넓혀 묻는다. 예정 일정은 실제 경험으로 가정하지 않는다.
- 여러 사건은 사건 ID별로 분리해 보관한다. 마지막에 사용자가 한 사건을 선택한다. 선택하지 않은 사건과 원문 근거도 보존하며 확인되지 않은 추출 값은 미확인으로 표시한다.
- 선택한 사건의 활동·장소·함께한 사람·각자의 행동·시간대·사물·소재·감정·고유 기억 단서를 점검한다. 대화에서 확인된 정보는 다시 묻지 않는다.
- 부족한 정보만 자연스러운 질문 하나씩으로 보완한다. 없음·모름·답변 거절을 구분하고 반복 질문하지 않는다. 소재는 확인된 활동에서 분류할 수 있으나 분류 출처를 기록한다.
- 그림은 선택한 장면의 확인된 사실만 사용한다. 생성한 사건 ID, 실제 생성 입력, 필수 사실 목록, 그림에 쓰지 않은 사건 ID, 화풍·품질·모델을 남긴다.
- 완성 후 별점은 그림 만족도가 아니라 선택한 경험의 중요도로 받는다. 선택하지 않은 사건에 별점을 복사하지 않는다. 건너뛰기는 미평가 상태로 보존한다.
- 최종 저장은 전체 이야기, 사건별 구조화 정보, 선택 결과, 생성 시점의 입력 스냅샷, 중요도와 매칭용 정보를 함께 보관한다.
- 완성 화면의 글도 선택한 사건만 보여준다. 전체 이야기와 다른 사건은 별도 보관·펼쳐보기로 확인한다.
- 최초 대화, 사건 선택 질문·응답, 선택 사건 추가 질문·답변, 미래 일정 입력, 별점 응답을 분리해 `conversation`에 보관한다. 질문은 사실의 근거가 아니며 사용자 답변과 확인 상태를 이용한다.
- 저장한 일기의 `experiences`에는 전체 원문 이야기와 각 사건, `matchingContext`에는 확인 상태가 있는 사건별 메타데이터, `generation.usedInformation`에는 실제 그림 입력 사건·사실과 제외한 사건 ID가 들어간다.
- 기본 화풍은 손으로 그린 따뜻한 색연필 그림이며 인물과 행동·핵심 사물은 명료하게 구별한다.

이 문서는 구현 기준이며 실제 개인화 매칭·판정기 정확도·인지 개선의 검증 결과가 아니다.
