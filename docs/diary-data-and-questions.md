# 매칭·그림 검증에 필요한 정보와 질문

현재 매칭 기준은 문헌을 참고한 설계 가설이다. SCD의 기억력 향상 효과가 검증된 추천 순위는 아니다. 이 프로토타입에는 자체 학습한 매칭·검증 모델이 포함되어 있지 않다.

## 날짜·장소·사람 외에 추가할 질문

| 정보 | 수집 수준 | 질문 예시 | 용도 |
|---|---|---|---|
| 활동·사건: 무엇을 했는가 | 필수 | 거기서 어떤 일을 하셨어요? | 같은 장소의 산책·식사·진료 구별, 관련 사건 검색 |
| 인물별 역할: 누가 무엇을 했는가 | 여러 사람의 행동 주체가 모호할 때 확인 | 자전거를 탄 분은 손녀인가요? | 인물–행동 관계 매칭, 생성 그림의 역할 교환 검사 |
| 그날을 구별할 구체적인 기억 단서 | 한 번 확인. 없음·모름·거절 허용 | 그때 특히 기억에 남는 장면이나 물건이 있나요? | 개인 고유 표현과 사건 구별 단서 보관 |

대화 전체에서 이미 나온 정보는 다시 묻지 않는다. ‘나는 벤치에 앉아 있었고 손녀는 자전거를 탔어요’라는 답변이면 활동과 역할이 함께 채워진다. 인물 수·핵심 사물·수량은 답변에서 추출하고 모호할 때만 확인한다.

필수 수집 항목이라고 매일 같은 질문을 모두 할 필요는 없다. 피로·거부·기억나지 않음을 표현하면 반복 질문으로 채우지 않는다. 활동 등 표현할 사실이 부족하면 그림 생성을 보류하고 글 기록을 남길 수 있게 한다. 단순히 드문 표현이라고 좋은 회상 단서라고 확정하지 않는다.

목적·감정·날씨·과거 사건과의 연결은 자발적으로 말한 경우 추가 저장한다. 감정이나 의료 내용을 모든 일기의 필수 질문으로 만들지 않는다. AI가 사건 사이의 인과관계를 지어내지 않는다.

## 내부 저장 항목

| 항목 | 필드 | 주의점 |
|---|---|---|
| 사건·선택 장면 | `id`, `scope`, `scene` | 실제 경험 한 장면. 다른 날·미래 일정은 분리 |
| 날짜·시간대 | `eventDate`, `dateStatus`, `timeOfDay` | 기록 생성일과 경험 날짜 구분. 모르면 null·unknown |
| 장소 이름·유형·ID | `place` | 같은 장소는 같은 ID. 고유명과 장소 유형 분리 |
| 사람 이름·관계·ID | `people[].id`, `name` | 같은 사람의 ID 유지. 실제 서비스에서는 사용자 범위로 관리 |
| 주요 활동 | `activity` | 무엇을 했는지 한 줄과 원래 설명 보관 |
| 인물별 행동 | `people[].action` | 누가 앉고 누가 탔는지 각각 저장 |
| 핵심 사물·수량 | `objects` | 활동에 중요한 사물만. 정확한 수를 모르면 null |
| 사용자 고유 단서 | `memoryCue`, `memoryCueStatus` | 직접 말한 표현. 있음·없음·모름·거절·미확인 구별 |
| 위치·상호작용 | `relation` | 확인된 관계만 선택적으로 보관 |
| 확인·출처 | `confirmed`, `source` | 추출 초안과 사용자 확인 구분. 서비스 통합 시 원래 발언·사진 출처 ID 연결 |
| 그림 인물 대응 | `people[].alias`, `visual` | A/B와 표현용 외모는 실제 경험의 외모 사실과 분리 |

사진·그림만으로 실명·가족관계·정확한 날짜·장소 고유명을 증명하지 않는다. 임의로 합의한 옷 색을 실제 경험 특성으로 학습하거나 매칭하지 않는다. 정확한 얼굴 일치에는 참조 자료와 별도 평가가 필요하다.

## 개인화 학습용 정보는 언제 받는가

아래는 생성 시 필수 질문이 아니라, 과거 자료로 회상할 때 기록할 정보다.

- 목표 과거 사건 ID와 실제 보여준 사진·그림·질문·단서 ID 및 종류.
- 제시 시점, 같은 자료의 노출 이력, 사건 이후 경과 시간.
- 회상 답변 원문, 사용한 힌트 단계, 건너뛰기·피로·거절 등 명시적인 반응.
- 그림에 보이는 내용의 반복과 추가로 떠올린 구체적인 경험을 구분한 주석.
- 독립적인 기록으로 확인 가능한 사실, 확인 불가 정보, 다른 사건과 섞였다고 확인된 정보를 구분한 평가.

짧고 느린 답변을 곧바로 회상 실패로 만들지 않는다. 만족도·선호·대화량과 기억의 정확도는 다르다. 쉬운 사건을 고르는 학습과 장기 기억을 높일 훈련 순서의 학습도 다른 목표다.

## 그림 생성 필수 조건

1. 사용자가 확인한 실제 경험 중 선택한 한 장면만 그린다.
2. 주요 인물의 수와 인물별 구별 설정을 유지한다.
3. 사람과 행동의 연결을 유지한다. 사람·사물이 각각 등장하는 것만으로 충분하지 않다.
4. 확인한 장소 유형, 핵심 사물과 명시된 수량을 반영한다.
5. 확인한 위치·상호작용이 있으면 유지한다.
6. 주요 인물·행동·사물이 검사 가능하도록 가림·축소를 피한다.
7. 다른 날, 내일 일정, 추천받은 과거 장면을 현재 그림에 섞지 않는다.
8. 모르는 날씨·옷·시각·새 주요 인물·새 행동을 실제 사실처럼 추가하지 않는다. 표현용 설정은 따로 관리한다.
9. 날짜·실명·가족관계·고유 지명은 내부 정보로 보관하며 그림 속 글자로 검증을 대신하지 않는다.
10. 생성과 검사에 같은 필수 사실 목록을 사용한다. 조건 수정 시 이전 판정은 무효화한다.

조건을 프롬프트에 넣는 것만으로 준수가 보장되지는 않아 결과를 검증해야 한다. 내부 기억 단서 문장 전체를 새로운 그림 속 물건으로 추가하지 않는다.

## 코드 연결

`public/diary-record.js`의 `collectionQuestions`는 활동·행동 주체·기억 단서에 빠진 부분을 확인한다. `matchingMetadata`, `sceneFacts`, `sceneGenerationPrompt`는 동일 기록을 사용한다.

프로토타입의 장면 편집에 적용했으며 원래 대화 앱을 강제 질문식으로 바꾸지는 않았다. 실제 대화에 연결할 때는 전체 대화에서 추출·확인한 정보에 적용하고 피로·거절 제어를 우선한다.
