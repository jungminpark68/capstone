# 그림일기 생성 → 임베딩/크로스 인코더 전달

최종 출력의 schema는 memory-itda-diary-events-v1입니다. candidate 래퍼와 크로스 인코더 점수·순위는 없습니다.

v0.19.1부터 초안은 사용자 발언을 보존하고 최종 본문은 확인한 항목으로 조합합니다. API 키가 있어도 본문을 모델로 다시 쓰지 않습니다. ‘응원했다’에서 ‘뿌듯했다’를 추측하지 않습니다. 감정은 직접 말한 표현만 사용하고, 답변이 없으면 질문하며 모름·거절이면 빈 배열로 전달합니다. 감정 라벨만으로 한국어 감정 문장을 만들어 채우지 않습니다.

## VS Code에서 시연

1. Node.js 22 이상을 준비하고 프로젝트 폴더에서 npm start를 실행합니다. Windows에서는 start-windows.cmd도 사용할 수 있습니다.
2. http://localhost:3000 에 접속합니다. PORT를 변경했다면 해당 포트를 사용합니다.
3. 설정 → 개발·시연용 설정 → 개발·연동 도구 표시를 켭니다. 일반 화면에서는 이 도구들이 보이지 않습니다.
4. 오늘 이야기 → 한 사건 선택 → 선택 사건의 빠진 정보 확인을 진행합니다.
5. 마지막 장면 확인 화면에서 **그림 없이 테스트 완료하기**를 누릅니다. **맞아요, 이 내용으로 그려주세요**는 실제 이미지 생성 버튼입니다.
6. 완성 화면에서 별점을 고르거나 **별점은 나중에 매길게요**를 누릅니다. 그림 생략 테스트도 이 단계를 거칩니다.
7. **매칭용 JSON · 개발·연동 → 매칭용 JSON 받기**로 파일을 받습니다. **전달 내용 확인**에서 같은 내용을 볼 수 있습니다.
8. 저장 후 **내 일기 → 일기 펼쳐보기 → 매칭용 JSON · 개발·연동**에서도 같은 ID와 양식으로 받습니다.

그림 생략 테스트는 이미지 생성 요청을 보내지 않습니다. API 키가 있으면 AI 대화·정보 추출·글 정리 비용은 발생할 수 있습니다. 완전히 API 비용 없이 반복하려면 키를 비워 실행하거나 http://localhost:3000/demo.html을 사용합니다. demo.html은 규칙 기반 체험 모드이며 실제 AI 품질을 보여주는 모드가 아닙니다.

그림 생략 여부는 마지막 확인 화면의 버튼으로 결정합니다. 개발 도구를 켰다는 이유만으로 정상 그림 생성을 생략하지 않습니다. 이전 버전의 전역 그림 생략 설정은 더 이상 사용하지 않습니다. 개발 도구 표시 여부만 브라우저에 저장합니다.

일반 **글로만 저장** 버튼은 없습니다. 그림 생략 테스트도 선택 사건 확인·별점 선택/건너뛰기·저장·동일 JSON을 거칩니다. 아직 별점을 결정하지 않았다면 저장과 JSON 다운로드를 막고 별점 위치를 안내합니다.

## 내보내기 구분

**매칭용 JSON 받기**는 어느 화면에서도 동일한 계약 검사와 변환 함수를 사용합니다. 완성 전·선택 미확인 기록은 오류를 안내하며, 전체 일기 저장 형식으로 대신 내려주지 않습니다. 이 형식에는 그림·전체 대화가 없습니다.

**전체 원본 백업 · 연동용 아님**은 개발 도구 안에서 별도로 펼칩니다. 파일명에 **전체원본백업**이 들어가며, 전체 대화·그림·다른 사건·생성 조건을 보관하는 복구용 원본입니다. 이 파일을 매칭 담당에게 전달하면 안 됩니다. 작성 중 원본 백업도 같은 이름으로 구분합니다.

기존 버전의 글로만 저장한 일기는 읽기와 원본 백업이 가능합니다. 장면 확인을 마치지 않은 과거 기록의 선택 정보나 별점을 임의로 만들어 내보내지 않습니다. 새 일기에서 확인 흐름을 마쳐 전달용 파일을 생성합니다.

## 필드 정의

- diaryId: 저장할 일기의 고유 ID. 내보내기 전에 준비하고 저장·다시 내보내기에도 유지합니다.
- experienceDate: 선택 사건에 기록된 경험 날짜. 작성/내보내기 시각으로 덮어쓰지 않습니다. 날짜가 미확인이면 null입니다.
- selectedEvent.eventId: 그림으로 선택한 사건의 기존 ID.
- selectedEvent.eventText: 최종 화면의 선택 사건 일기 본문. 추가 답변을 반영합니다. 그림을 보고 역으로 만든 설명이 아닙니다.
- selectedEvent.elements: place/person/activity/object/emotion 다섯 개의 문자열 배열.
- selectedEvent.importance: 선택한 경험의 1~5 정수 또는 null. scale은 항상 문자열 1-5입니다.
- otherEvents: 선택하지 않은 사건마다 기존 ID·사건 설명·다섯 요소를 보관합니다. 별점을 추가하지 않습니다. 없으면 빈 배열입니다.

elements 매핑:

- place: 사용자가 말한 장소 이름. 없을 때 확인된 일반 장소 유형을 사용합니다.
- person: 저장된 인물 이름/관계. 본인인 나도 포함될 수 있습니다.
- activity: 대표 활동과 확인한 인물별 행동을 담습니다. 인물–행동 연결은 나: 물에 뜨는 연습 같은 문자열로 보존합니다.
- object: 실제로 말한 사물 이름. 확인한 수량이 있으면 이름과 함께 적습니다. 예: 수영 보조용품 1개.
- emotion: 직접 말한 감정 원문을 보존합니다. 원문이 없으면 빈 배열이며 감정 코드만으로 문장을 만들지 않습니다. 표정·성공·응원 행동으로 감정을 추측하지 않습니다.

정보가 없음·모름·거절·아직 묻지 않음이면 해당 배열은 비웁니다. 오래된 값이 남아 있어도 명시적인 미확인 상태를 우선합니다. 다른 사건은 상세 질문을 모두 하지 않았을 수 있으므로 알려진 정보만 내보냅니다. 이 때문에 다른 사건을 선택 사건의 답으로 채우지 않습니다.

현재 필수 질문은 장소·인물·활동·물건·감정을 이미 포함하므로 추가 질문 종류를 늘리지 않았습니다. 수영/수영장/스포츠센터의 규칙 기반 인식을 보완했고 산책에서 책을 사물로 잡는 오류와 행동 답변의 주어 중복을 고쳤습니다.

## 보관 정보와 전달 정보

전체 대화·원문·그림·생성 당시 조건·그림 구별용 옷 색은 앱 내부 저장과 명시적인 전체 원본 백업에 남습니다. 매칭용 JSON에는 이미지와 전체 대화, 표현용 외모, 모델 점수를 넣지 않습니다. 그림 때문에 임의로 정한 색과 실제 경험에 등장한 사물 색을 구분합니다.

선택 사건을 확인하지 않은 기록이나 사건 ID가 맞지 않는 그림은 내보내기를 막고 이유를 표시합니다. 구조화 정보가 없는 오래된 일기는 그대로 읽을 수 있지만 선택 사건을 새로 지어내지는 않습니다.

## 받는 팀원에게 전달

diary-events-v1.schema.json과 diary-events-v1.example.json을 함께 전달합니다. JSON Schema의 date 포맷 검사를 활성화합니다. 선택 사건과 다른 사건의 eventId가 서로 다른지도 확인해야 합니다.

임베딩·검색의 주 기준은 selectedEvent입니다. otherEvents는 분리한 부가 문맥이며 실제 활용 방식은 후속 담당과 합의합니다. 이 코드에서 임베딩·크로스 인코더·과거 일기 추천을 실행하지는 않습니다.

서버 변환 확인용 엔드포인트는 POST /api/diary-events-export입니다. 앱의 기존 전체 저장 기록(entry)을 JSON 본문으로 보내면 위 전달 형식으로 변환하고, 잘못된 기록은 400을 반환합니다. 이 엔드포인트는 외부 AI를 호출하지 않습니다. UI의 JSON 파일 받기는 브라우저에서도 동일 변환 함수를 사용합니다.

예시 파일은 구조 설명용입니다. 실제 저장한 일기의 결과는 앱에서 내려받아 후속 담당의 입력으로 연결해 확인합니다.
