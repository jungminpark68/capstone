# 🌸 기억잇다 — AI 그림일기 웹 MVP

오늘의 사진 0~5장 또는 대화만으로 시작 → 회상 대화 → 일기와 그림 장면 확인·수정 → AI 삽화 생성 → 저장합니다. 최종 모바일 앱에서도 같은 서버 API를 호출할 수 있습니다.

## 여러 날짜의 일정 함께 등록 · v0.7

앞으로의 일정 단계에서 **내일·모레와 구체적인 날짜의 일정을 한 번에 최대 5개까지** 말하고, 날짜별 후보를 확인해 등록할 수 있습니다.

- `내일 오전 11시에 치과에 가고 모레 오후 2시에 은행에 가요`처럼 한 문장에 여러 날짜를 말해도 각각 분리합니다. 시간 표현이 이어지는 `모래`는 `모레`의 오타로 해석하되, 모래놀이의 모래는 날짜로 바꾸지 않습니다.
- `11월 10일`, `2026-11-10`, `10일`, `다음 주 월요일`, `금요일`, `3일 뒤`, `다음 달 5일` 같은 날짜 표현을 지원합니다. 월 없이 `10일`만 말하면 기록 날짜 이후 가장 가까운 유효한 10일을 후보로 잡습니다. 월일만 말하면 앞으로 다가오는 해당 월일을 사용합니다.
- 날짜를 말하지 않은 후속 일정은 앞서 말한 날짜를 이어받습니다. 날짜를 전혀 말하지 않은 입력은 기존처럼 내일을 기본 후보로 사용합니다. 모든 상대 날짜는 브라우저의 오늘 또는 사용자가 선택한 **일기 기록 날짜**를 기준으로 계산합니다.
- `다음 주에`처럼 요일이 없거나 유효하지 않은 날짜는 날짜 칸을 비워둡니다. 사용자가 날짜를 선택하기 전에는 등록하지 않습니다. 이미 지난 날짜의 이야기는 미래 일정 후보에서 제외합니다.
- 각 일정 카드에서 이름·날짜·시간·장소를 고칠 수 있습니다. **다른 방법으로 진행하기 → 직접 일정 추가하기**는 기존 후보를 유지하고 새 카드를 추가합니다. 오전·오후가 없는 시간은 추측하지 않습니다.
- 같은 장소·시간의 할 일이라도 날짜가 다르면 각각 등록합니다. 날짜·제목·시간·장소가 모두 같은 중복만 제외합니다. 5개를 넘으면 조용히 자르지 않고 나누어 등록하도록 안내합니다.
- AI에 날짜별 계산 결과를 전달하고, AI가 날짜를 잘못 배정하거나 일부 날짜를 빠뜨리면 전체 날짜를 포함한 규칙 기반 후보로 대체해 확인받습니다. 복잡한 말투는 AI 모드가 더 잘 정리할 수 있으며, 체험 모드는 간단한 문장과 숫자 시간을 중심으로 처리하므로 확인 화면에서 수정해 주세요.
- 오늘 대화에서 나온 여러 미래 계획도 일정 단계로 함께 옮기고 오늘 일기에서는 분리합니다. 수정한 후보는 새로고침 후 **이어서 쓰기**로 복원됩니다. 저장 전까지 실제 캘린더에는 나타나지 않습니다.

## 편안한 대화 · 일정 문맥과 완료 체크 · v0.6

- **그만 캐묻기:** “딱히 이야기한 것은 없어요”, “불편해요”, “분위기가 무거웠어요” 등에는 같은 주제의 분위기·감정·대처를 더 묻지 않고 주제 변경을 제안합니다. 다른 이야기도 없으면 짧게 마무리합니다. 명시적인 거절 신호는 AI 호출 전에 공통 규칙으로 처리하며, 새로운 경험을 이야기하면 그 대화는 이어갈 수 있습니다. **다른 이야기 할래요** 버튼으로도 주제를 넘길 수 있습니다.
- **일정의 앞뒤 문맥:** 내일 일정 추출 API에는 입력 문장뿐 아니라 오늘 대화 전체와 예정 일정도 전달합니다. “병원에 갔다 왔어요. 내일 11시에 또 오래요”는 병원 방문과 연결하며, 확인된 병원명이 하나면 그 장소를 활용합니다. 여러 장소가 가능하면 추측하지 않습니다. 문맥으로 채운 장소는 후보에 안내하고 등록 전에 확인받습니다. 오전·오후가 없는 11시는 여전히 직접 확인해야 합니다.
- **일정 추출 실패:** AI 연결이나 응답 형식에 문제가 생기면 대화 기반 후보를 준비하고 안내합니다. 후보는 자동 등록하지 않으며, **일정 연결 문제 자세히 보기**에서 안전한 오류 설명을 확인할 수 있습니다. 후보와 안내는 임시 저장됩니다. API 키가 없어도 규칙 기반 체험은 가능합니다.
- **완료 체크:** 달력의 각 일정에서 **완료로 표시**를 체크하거나 해제할 수 있습니다. 완료는 새로고침·일정 수정 후에도 유지합니다. 월간 달력에는 남은 일정 개수 또는 ✓ 완료를 표시합니다. 완료한 일정은 다시 수행 여부를 묻는 첫 질문의 대상으로 삼지 않습니다. 미완료 일정은 날짜가 지나도 그대로 남으며, 자동 삭제·위험 판단·보호자 통보·자동 이월은 하지 않습니다.

### 새 버전인데 기록이 남는 이유와 완전 초기화

기록은 소스 폴더가 아니라 **브라우저의 주소(프로토콜·호스트·포트)별 IndexedDB와 localStorage**에 저장합니다. 같은 브라우저에서 `http://localhost:3000`을 계속 쓰면 새 ZIP을 받아도 기존 기록이 유지되는 것이 정상입니다. `localhost`와 `127.0.0.1`, 다른 포트, 다른 브라우저는 별도 저장소입니다.

처음 상태로 테스트하려면 **설정 → 기록 관리 → 모든 기록 초기화 → 모든 기록 지우기**를 선택하세요. 다른 기억잇다 창은 닫고 진행합니다. 저장한 일기, 작성 중인 사진·대화·일정 후보, 캘린더 일정·완료 표시, 큰 글씨 설정과 이전 버전의 로컬 기록을 지웁니다. 취소하면 그대로 보존하며, 삭제 후에는 되돌릴 수 없습니다. 필요한 일기는 미리 파일로 보관하세요. 서버의 `.env`, API 키, 프로젝트 파일과 다른 앱의 저장소는 건드리지 않습니다. 새 버전 설치 시 자동 초기화하지 않습니다.

초기화 메뉴가 없는 구버전에서는 Chrome/Edge의 개발자 도구(F12) → Application(애플리케이션) → Storage(저장소) → Clear site data(사이트 데이터 삭제)로 현재 앱 주소의 데이터를 지운 뒤 새로고침할 수 있습니다.

## 한눈에 보는 달력과 오늘 일기 · v0.5

- **월간 달력:** 일요일부터 토요일까지 한 달을 펼쳐 봅니다. 일정이 있는 날짜에는 ●와 개수가 표시되며, 넓은 화면에는 첫 일정명도 표시합니다. 날짜를 누르면 달력 아래에 그날의 전체 일정·시간·장소가 나옵니다. 오늘과 선택한 날짜를 구분하고, 이전/다음 달 및 오늘로 이동을 지원합니다. 먼 날짜는 접힌 **날짜로 바로 찾기**에서 선택할 수 있습니다. 키보드는 화살표·Home/End·PageUp/PageDown으로 이동합니다.
- **오늘이 기본:** 첫 화면의 **오늘 이야기 시작하기**, **사진과 함께 시작할래요**는 브라우저 현지의 오늘 날짜로 새 일기를 시작합니다. 달력에서 과거 날짜를 보거나 예전 임시 기록을 이어 썼더라도 새 일기 날짜에 영향을 주지 않습니다. 다른 날의 일기는 **다른 날의 일기도 쓸 수 있어요**를 펼친 뒤 날짜별 시작 버튼으로 명시적으로 시작합니다. 과거 임시 기록은 해당 날짜가 표시된 **쓰던 이야기 이어쓰기**로 계속 쓸 수 있습니다.
- **단순한 화면:** 큰 주 버튼을 우선 보여주고, 글씨 크기는 상단 **설정**, 일정 수정·삭제는 일정 카드의 **고치기 · 삭제**, 직접 일정 입력은 **다른 방법으로 진행하기**, 일기 대화 재개·파일 보관은 확인 화면의 펼침 메뉴에 모았습니다. 기존 사진·음성·휴식·텍스트 저장·임시 저장 기능은 유지합니다.
- 캘린더 날짜를 선택하는 것만으로 일기 날짜가 바뀌지는 않습니다. 일정을 수정할 때는 달력 대신 입력 폼에 집중하며, 저장하거나 돌아가면 달력으로 복귀합니다. 기록·일정 저장소와 기존 데이터는 그대로 사용합니다.

## 일정과 이어지는 대화 · v0.4

담당 기능을 **오늘 일정 확인 → 경험에 따른 꼬리질문 → 내일 일정 확인·등록 → 오늘 그림일기 생성** 순서로 연결했습니다.

1. 상단 **달력 → 날짜 선택 → 이 날에 일정 적기**에서 오늘 일정(예: 오전 10시 병원 방문)을 저장합니다. 일정은 날짜별로 조회·수정·삭제할 수 있습니다.
2. 첫 화면에서 **오늘 이야기 시작하기** 또는 **사진과 함께 시작할래요**를 선택합니다. 오늘 일정이 있으면 그 일정이 실제로 어떻게 되었는지 묻습니다. 일정은 실행한 사실로 취급하지 않습니다. 일정이 없으면 자유 대화로 시작합니다. 여러 일정은 시간순으로 정렬해 첫 일정을 대화의 출발점으로 삼습니다.
3. “병원은 취소하고 딸과 공원에서 산책했어요”처럼 말하면 실제 경험에 맞춰 후속 질문을 합니다. 충분히 이야기하거나 **오늘 이야기 마치기**를 누르면 내일 일정 단계로 넘어갑니다.
4. “내일 오후 3시에 치과에 가요”처럼 내일 할 일을 말하고 **일정 확인하기**를 누릅니다. 여러 일정은 줄을 나누어 적습니다. AI 모드는 모델로 후보를 추출하며, 체험 모드는 간단한 문장·숫자 시간만 처리합니다. 체험 모드도 “치과에서 11시에 와야된데요” 같은 방문 표현을 “치과 방문”으로 정리하고, 말한 장소(예: 치과, 행복치과)를 채웁니다. 명시하지 않은 장소·주소는 추측하지 않으며, 그 밖의 표현은 원문을 후보 이름으로 사용해 직접 수정할 수 있게 합니다. 복잡한 표현은 **직접 일정 적기**로 입력할 수 있습니다.
5. 할 일·날짜·시간·장소를 확인하고 **맞아요, 등록하고 일기 만들기**를 눌러야 캘린더에 저장됩니다. “3시”처럼 오전·오후가 불명확하면 시간을 추측하지 않습니다. 시간은 비워둘 수 있고, 일정이 없으면 **일정 등록 없이 일기 만들기**로 넘어갑니다. 동일한 날짜·이름·시간·장소의 일정은 중복 저장하지 않습니다.
6. 오늘 경험으로 만든 일기 초안을 확인·수정한 뒤 기존 방식으로 그림을 생성하거나 글만 저장합니다. 내일 일정 답변은 오늘 일기 API에 전달하지 않습니다. 오늘 대화에 섞인 명시적 미래 계획도 문장·절 단위로 제외하고, AI에는 예정과 실제를 구분하도록 지시합니다. 규칙 기반 분리는 보수적이므로 복잡한 시제는 초안에서 확인·수정해야 합니다.

캘린더와 작성 중인 일정 후보는 **이 브라우저의 IndexedDB**에 저장합니다. 기존 일기·임시 저장은 DB 버전 업그레이드 시 보존합니다. 확인 전 후보는 일정 목록에 나타나지 않으며, 내일 일정 화면도 새로고침 후 **이어서 쓰기**로 복원됩니다. 일정 저장 후 일기 생성이 실패해도 일정은 유지되며 재시도 시 중복 등록하지 않습니다.

‘내일’은 **선택한 기록 날짜의 다음 날**, ‘모레’는 이틀 뒤입니다. 여러 날짜와 구체적인 날짜의 현재 지원 방식은 v0.7 안내를 참고하세요. 다른 날의 일기를 쓸 때는 화면에 표시된 실제 날짜를 확인하세요. 시각은 브라우저의 현지 날짜·시간을 기준으로 합니다.

이 버전은 앱 내부 캘린더입니다. 휴대폰·Google 캘린더 동기화, 일정 푸시 알림, GPS·보호자 알림, 과거 사진 매칭은 포함하지 않습니다. AI 모드에서는 질문 생성 시 오늘 예정 일정이, 일정 추출 시 입력한 내일 계획이 외부 AI로 전달됩니다.

### 확인해 볼 시나리오

- 오늘 병원 일정을 등록한 뒤 취소했다고 답하기 → 병원을 다녀왔다고 일기에 쓰지 않는지 확인.
- 오늘 산책 경험을 이야기한 뒤 내일 치과 일정 등록 → 일기에는 산책, 캘린더에는 치과가 각각 남는지 확인.
- “내일 3시에 친구 만나기” → 오전·오후를 추측하지 않고 직접 시간 확인.
- 일정 등록 전 새로고침, 등록 후 일기 저장, 일정 수정·삭제, 내일 일정 건너뛰기.

## 윈도우에서 시작하기

1. https://nodejs.org 에서 Node.js **24 LTS**를 설치합니다. VS Code를 종료했다가 다시 열어 PATH를 적용하세요.
2. ZIP의 **압축을 모두 풀기**를 선택합니다. VS Code에서 `package.json`과 `server.js`가 있는 `memory-diary` 폴더를 엽니다.
3. `.env.example` 파일을 복사해 `.env`로 이름을 바꿉니다. VS Code에서 새 파일 `.env`를 만들고 예제 내용을 복사해도 됩니다.
4. `.env`의 `DIARY_API_KEY=` 뒤에 본인의 실제 API 키를 붙여넣고 저장합니다. 키를 채팅·GitHub·브라우저 코드에 넣지 마세요. `.env`는 Git에서 제외합니다.
5. **터미널 → 새 터미널**을 열고 아래를 실행합니다.

```powershell
node --env-file-if-exists=.env server.js
```

또는 압축을 푼 폴더에서 `start-windows.cmd`를 더블클릭합니다. 실행 파일은 `.env`가 없을 경우 예제를 복사하며, 실제 키는 직접 입력해야 합니다. `.env`를 수정했다면 서버에서 `Ctrl+C`를 누른 후 다시 실행하세요.

6. Chrome 또는 Edge에서 **http://localhost:3000** 을 엽니다. 터미널은 켜둡니다. 종료는 `Ctrl+C`입니다. Node.js 22 이상이 필요하며 `npm install`은 필요하지 않습니다.

```dotenv
DIARY_API_KEY=본인의_실제_API_키
DIARY_MODEL=gpt-4o-mini
DIARY_IMAGE_MODEL=gpt-image-2.5-sunburst
PORT=3000
```

API 키가 없으면 체험 모드로 작동합니다. 사진을 분석하지 않고, 이전 발언의 키워드와 질문 기록을 이용해 반복을 피합니다. 실제 AI가 생성한 그림인 것처럼 대체 이미지를 표시하지 않습니다. 단독 `demo.html`도 체험용이며, 키를 넣어도 이 파일만 열어서는 실제 AI를 호출하지 않습니다.

## 문제 해결

- `node`를 찾지 못함: Node.js 설치 후 VS Code를 완전히 종료하고 다시 열기.
- `--env-file-if-exists` 옵션 오류: Node.js 24 LTS로 업데이트.
- 체험 모드가 계속 표시됨: `.env.txt`가 아닌 `.env`인지, 파일이 `server.js`와 같은 폴더인지 확인하고 서버 재시작.
- 3000 포트 사용 중: 이전 서버를 종료하거나 `.env`의 PORT를 3001로 바꾼 뒤 해당 포트로 접속.
- AI 인증 오류: API 키 유효성 확인. ChatGPT 구독과 API 결제는 별개입니다.
- 이미지 권한 오류: 모델 접근 권한·조직 인증·API 결제 상태 확인.
- 저장 공간 부족: 작성 화면에서 JSON 파일로 보관. 파일 가져오기 기능은 아직 없습니다.

## AI 및 개인정보

회상 대화/글은 이미지 입력·JSON 출력을 지원하는 Chat Completions 모델을 사용합니다. 삽화는 Images Generations API에서 1024×1024, low quality, JPEG로 생성합니다. 기본값은 각각 `gpt-4o-mini`, `gpt-image-2.5-sunburst`이며 계정에서 이용 가능한지 확인해야 합니다. 실제 AI 품질과 권한 검증에는 유효한 키가 필요합니다. 생성과 재생성에 API 비용이 발생합니다.

사진과 전체 대화는 질문·초안 생성 시 OpenAI로 전송합니다. 그림 생성에는 사용자가 확인한 제목·본문·장면만 전송합니다. 원본 얼굴을 복제하는 사진 편집 API는 사용하지 않습니다. `prompts.js`에서 역할별 프롬프트를 수정할 수 있습니다.

그림은 실제 사진과 다른 **AI 삽화**임을 표시합니다. 일기 글이나 제목만 고칠 때는 기존 그림을 그대로 사용합니다. 그림 장면을 바꾸면 재생성하거나 글만 저장할 수 있습니다. API 실패 시 작성 내용을 유지하고 재시도합니다. 그림 없이 글만 저장할 수도 있습니다. 생성 결과는 사용자 확인이 필요합니다.

작성 중 사진·대화·초안과 저장한 일기는 이 브라우저의 IndexedDB에 보관합니다. 선택한 사진은 축소한 사본을 임시 저장하며, 완성 일기에는 업로드 사진과 대화 전체를 포함하지 않습니다. 저장 완료 시 임시 기록은 지웁니다. 이전 v2 localStorage 일기는 일기장을 열 때 가져오며 원본은 삭제하지 않습니다. 계정·서버 DB·기기 간 동기화·가족 음성 합성은 없습니다. 읽어주기는 브라우저 기본 TTS, 선택적인 말하기는 브라우저 SpeechRecognition입니다. 음성은 브라우저 서비스로 전달될 수 있습니다. 지원하지 않거나 권한을 거부하면 글로 입력합니다. 작성 내용은 약 0.5초 후 임시 저장하며 새로고침 후 첫 화면에서 이어 쓸 수 있습니다. 저장소 차단·용량 부족 시 안내하고 JSON 파일 보관을 제공합니다. 시크릿 모드나 브라우저 데이터 삭제로 기록이 사라질 수 있습니다. 개발 서버는 이 컴퓨터에서만 접속할 수 있도록 127.0.0.1에 바인딩합니다. 공개 운영에는 인증·호출 제한·보관 정책이 별도로 필요합니다.

Flickr8k/30k는 사용 조건을 확인하고 사진 경로 시연에 활용하세요. 촬영 날짜·관계·감정을 캡션만으로 사용자 경험으로 해석하지 않습니다. 데이터셋 자동 다운로드나 학습은 포함하지 않습니다.

## API / 개발

- `GET /api/config`: 키 설정 여부. 실제 인증 성공을 뜻하지 않음.
- `POST /api/question`: `{turns:[{question,answer}],photos:[JPEG 데이터 URL]}` → `{question,ready,rest?,mode}`
- `POST /api/plans`: `{date:"YYYY-MM-DD",text:"내일 오후 3시에 치과",turns:[{question,answer}],todayEvents:[{title,date,time,location,completed?}]}` → `{events:[{title,date,time,location,inferredFromContext?}],mode,notice?,diagnostic?}`. 확인 전 여러 날짜의 일정 후보만 반환하며 서버에는 저장하지 않습니다. 불분명한 날짜는 빈 문자열이며 확인 화면에서 선택해야 합니다. 최대 5개, 입력 2000자.
- 질문·초안 입력에는 선택적으로 `date`, `todayEvents:[{title,date,time,location}]`를 전달할 수 있습니다. 일정 날짜는 기록 날짜와 같아야 합니다.
- `POST /api/draft`: 같은 입력 → `{title,body,scene,mode}`
- `POST /api/illustration`: 확인한 `{title,body,scene}` → `{image: JPEG 데이터 URL,mode}`

사진 최대 5장(각 URL 150만 문자), 요청 전체 8MB, 답변당 2000자 제한. 브라우저에서 최대 900px JPEG로 축소합니다. 대화는 최대 6회이며 충분한 이야기가 모이면 일찍 정리합니다. 이전 답변·건너뛴 질문을 반복하지 않도록 설계합니다. 규칙 기반 체험은 복잡한 문맥을 완전히 이해하지는 못합니다.

```powershell
npm test
npm run build:demo
```

테스트는 입력 검증·반복 질문 방지·조기 종료·HTTP API·모의 AI 응답을 검증합니다. 실제 OpenAI 생성 검증과 구분하세요. `build:demo`는 스타일과 스크립트를 포함한 단일 `demo.html`을 재생성합니다.

HTTP 오류에는 민감한 원문 대신 오류 코드(code)와 문제 옵션(param)이 표시됩니다. 오류가 계속되면 이 식별자와 발생 단계를 알려주세요. API 키는 공유하지 마세요.


## 어르신을 위한 화면 구성 (v0.3)

- 시작 화면: 사진 보며 이야기하기 / 사진 없이 이야기하기 두 가지 선택. 다른 날짜는 선택 메뉴 안에 둡니다.
- 대화 화면: 질문 하나에 집중하고 이전 대화는 접어서 표시합니다. 읽어주기·선택적 마이크·잘 모르겠어요·쉬기를 제공합니다. 사진은 개별 삭제·추가할 수 있습니다.
- 확인 화면: 입력창 대신 일기 종이 형태로 먼저 보여줍니다. '조금 고칠게요'를 누를 때만 수정칸을 엽니다. '맞아요, 그림으로 남겨주세요'가 내용 확인을 겸합니다.
- 글 저장: 그림 생성이 막혀도 이야기를 글로 저장할 수 있습니다.
- 이어쓰기: 대화·사진·초안을 이 기기에 임시 저장합니다. 새로 시작할 때는 기존 쓰던 이야기를 바꾸는지 확인합니다.
- 일기장: 카드로 목록을 보고 일기를 펼쳐 읽습니다. 삭제 전에 확인합니다.
- 글씨 크게: 헤더 버튼으로 확대하며 다음 방문에도 유지합니다. 키보드 초점·상태 안내·줄어든 모션 설정을 지원합니다.

기본 문자는 20~21px, 주요 버튼은 최소 56px이며 저시력 사용자의 실제 접근성 평가를 대신하지 않습니다. 브라우저 음성 인식은 기기·네트워크·권한에 따라 달라집니다. 가족 음성은 아직 지원하지 않습니다. 크림색·초록색과 차분한 문구를 쓰되 점수나 진단 표현은 쓰지 않습니다.
